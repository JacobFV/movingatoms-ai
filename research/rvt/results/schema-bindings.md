# Embedded schema identifies the footer

The observed footer tags resolve to **`SignatureMarker`** in each fixture's own
`Formats/Latest` schema. Its two declared field names are `m_privateSignature`
(the counted binary field) and `m_publicSignature` (the string containing
`Data generated by Autodesk® Revit®`). This is evidence from file bytes, not
from Revit binaries, debugging, disassembly, or a proprietary SDK.

| Revit fixture profile | ContentMarker | ContentKey | SegmentMarker | SegmentCheckback | SignatureMarker |
| --- | --- | --- | --- | --- | --- |
| 2023 | 0x365 | 0x364 | 0xe4e | 0xe47 | 0xe61 |
| 2024 | 0x37b | 0x37a | 0xe7c | 0xe75 | 0xe8f |
| 2025 | 0x391 | 0x390 | 0xed9 | 0xed2 | 0xeee |

`ContentMarker` declares `m_oContentKey` and `m_nElementCount`; `ContentKey`
declares `m_guidKey`. The continuation GUIDs should therefore be described as
content keys, not editing episodes. `SegmentMarker` declares
`m_continuationBits`, `m_objectCount`, `m_segmentSize`, and
`m_uncompressedSize`; `SegmentCheckback` repeats `m_segmentSize`.

`schema_probe.py` builds the small checked-in Rust helper against a clean local
checkout of public rvt-rs revision `b6086d41b9758fd9b92f42f0a47b8345b9c58056`.
The ordinal grammar consumes each complete inflated schema without error,
and all five names/tags match the observed partition bytes. Field declarations
come from the reader's separate best-effort field parser; field-type guesses
are not treated as an implementation specification. Full results for all six
fixtures are in `schema-bindings.json`.

The class/field names make an authentication role a stronger hypothesis than
an arbitrary checksum. **They do not establish the cryptographic algorithm,
keying, covered bytes, or Autodesk enforcement.** No key recovery or
proprietary implementation access has been attempted. The room edit still
carries a stale, unexplained private-signature value. Independent reader
success cannot settle Autodesk acceptance.

Two source content groups have empty private and public signature fields.
Additional candidates clear both fields on the edited/nonedited base group,
using the observed empty representation. This tests whether unsigned content
is accepted; it does not assume empty signatures are valid for nonempty data.

```sh
python3 research/rvt/schema_probe.py --reader-source /path/to/pinned/rvt-rs research/rvt/local/core2024.rvt research/rvt/local/einhoven.rvt research/rvt/local/RE1-*.rvt
```
